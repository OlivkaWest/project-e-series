# VIDEO_DUMP — сюда загружаются клипы из Grok

## Как называть файлы

Единственное требование — **номер шота в имени**. Всё остальное неважно.

```
EP01_SH001_v1.mp4
EP01_SH001_v2.mp4
EP01_SH001_v3.mp4
EP01_SH002_v1.mp4
...
```

Годится и `SH001_1.mp4`, и `sh001-вариант2.mp4`. Не годится `video_final(3).mp4`:
по такому имени я не пойму, к какому шоту относится клип, а варианты одного шота
отличаются деталями, которые по содержимому не всегда различишь.

Грузить можно **все варианты**, не только лучший. Отбор — моя работа: я прогоню
каждый через ffprobe и разбор по кадрам и выберу.

## Ограничения загрузки через веб-интерфейс GitHub

* до **25 МБ** на файл;
* до 100 файлов за раз;
* один слишком тяжёлый файл валит всю партию целиком, а не пропускается.

Клип 720p на 5–10 секунд обычно весит 5–15 МБ и проходит. Если Grok отдаст
что-то тяжелее 25 МБ — скажите, дам команду для сжатия без потери качества
картинки, либо заберём файл другим путём.

## Что происходит дальше

```
клипы приезжают сюда
        ↓
ffprobe: разрешение, fps, длительность, битрейт
        ↓
покадровый разбор: идентичность, камера, физика, артефакты, континьюити
        ↓
оценки по семи параметрам, APPROVED или REGENERATE
        ↓
принятые клипы режутся по монтажному листу
        ↓
сборка, звук, субтитры, нормализация, QA, экспорт
```

## Технические требования к финалу

| Параметр | Значение |
|---|---|
| Разрешение | 1080×1920 |
| Частота кадров | 30 fps |
| Длительность | 35 секунд |
| Речь | −16 LUFS |
| Мастер | −14 LUFS, пики ≤ −1 dBTP |

Если Grok отдаёт 720×1280 — это нормально, апскейл до 1080×1920 делается
на этапе экспорта. Важнее чистая картинка, чем разрешение исходника.
