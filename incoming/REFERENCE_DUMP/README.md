# REFERENCE_DUMP — свалка референсов для разбора

Сюда владелец вручную загружает **все** изображения, накопившиеся по сериалу:
утверждённые, забракованные, промежуточные, персонажей, локации, раскадровку,
мастер-кадры и любые другие визуалы.

**Сортировать при загрузке не нужно.** Разбор — моя работа, не ваша.

## Правила папки

1. **Ничего отсюда не удаляется.** Даже то, что будет забраковано. Папка остаётся
   архивом происхождения: по ней потом видно, откуда взялся каждый принятый кадр.
2. Переименовывать файлы не нужно. Классификация идёт по содержимому изображения,
   а не по имени.
3. Дубликаты класть можно и нужно — их выявление входит в разбор.

## Что здесь настроено технически

| Файл | Зачем |
|---|---|
| `.gitattributes` | выводит папку из-под Git LFS |
| `.gitignore` | снимает корневой запрет на `*.mp4`, `*.mov`, `*.wav`, `*.mp3` |

Обе настройки нужны, чтобы файлы физически доезжали до разбора. В корне репозитория
картинки уходят в Git LFS, а хост `lfs.github.com` закрыт политикой исходящего
трафика удалённой сессии: файлы в LFS приехали бы сюда указателями, а не картинками.
Политика не обходится — обходится маршрут файлов.

## Ограничения загрузки через веб-интерфейс GitHub

- до **25 МБ** на файл;
- до **100 файлов** за одну загрузку — если файлов больше, грузите несколькими
  заходами, это нормально;
- перетаскивание папки целиком работает, вложенность сохранится.

## Что происходит дальше

```
владелец грузит всё
        ↓
разбор по содержимому
        ↓
каждому файлу — постоянный ID и предполагаемый статус
        ↓
показ владельцу группами, с картинками
        ↓
спорные разбираются поимённо
        ↓
утверждённое копируется в assets/final-references/
        ↓
assets/ASSET_REGISTRY.md становится источником правды
```

Статусы разбора: `APPROVED` · `REJECTED` · `DUPLICATE` · `OUTDATED` · `UNCLEAR` · `NEW`.
