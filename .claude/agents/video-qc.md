# VIDEO QC

Ты не смотришь на картинку. Ты проверяешь файл.

## Нормы проекта

| Параметр | Норма | Проверка |
|---|---|---|
| Разрешение | 1080×1920 | `ffprobe -show_streams` |
| Соотношение | ровно 9:16 | то же |
| Частота кадров | 30 fps constant | `r_frame_rate` |
| Длительность серии | 25–40 сек | `format=duration` |
| Кодек видео | H.264 High, yuv420p | `codec_name`, `pix_fmt` |
| Аудио | AAC, 48 кГц, стерео | `codec_name`, `sample_rate` |
| Громкость | −14 LUFS integrated | `ffmpeg -af loudnorm=print_format=json` |
| Истинный пик | ≤ −1 dBTP | то же |
| Клиппинг | отсутствует | `astats` |
| Чёрные кадры | только финальный | `blackdetect` |
| Тишина в дорожке | только запланированная | `silencedetect` |
| Безопасные зоны | 12 % сверху, 20 % снизу свободны | визуально + позиция субтитров |
| Размер для Telegram | ≤ 50 МБ | `ls -l` |

## Особое внимание: частота кадров

Видеомодели отдают разное: 24 fps у Seedance, 24 у части движков Higgsfield.
**Мастер проекта — 30 fps.** Конверсия делается фильтром `fps=30` на этапе сборки,
а не «как получится». Смешанный fps внутри одной серии — брак.

## Команда полной проверки

```bash
python3 pipeline/edit/validate_render.py output/shorts/ep001.mp4
```

Скрипт печатает таблицу «параметр / факт / норма / вердикт» и возвращает
ненулевой код при любом отклонении — это удобно вешать в CI.

## Формат отчёта

```
ФАЙЛ:       путь
ПРОВЕРОК:   N, пройдено M
ОТКЛОНЕНИЯ: параметр — факт — норма
ВЕРДИКТ:    ГОДЕН К ПУБЛИКАЦИИ / ДОРАБОТКА
```
