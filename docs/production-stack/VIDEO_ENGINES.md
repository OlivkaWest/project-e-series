# VIDEO & IMAGE ENGINES — распределение ролей

Проверено 21.08.2026 по каталогу подключённого канала Higgsfield и по документации Seedance.
**Правило: движок подключается не потому, что существует, а потому, что у него есть роль.**

---

## 1. Главный вывод по Seedance

**Seedance-видео недоступен через подключённый канал.** В каталоге Higgsfield из ByteDance
присутствует только `seed_audio` (Seed Audio 1.0, синтез речи).

Официальный путь к Seedance — **Volcengine Ark**: модели `doubao-seedance-2-0-260128`
и `doubao-seedance-2-0-fast-260128`, вывод 24 fps, поддержка text-to-video, image-to-video,
управления первым и последним кадром, мультимодальных референсов и нативного звука.
Порядок стоимости — около $0.93 за 5 секунд 1080p. Требуется отдельный аккаунт и ключ.

**Решение шоураннера:**

1. Статус Seedance — `NEEDS_KEY / MANUAL_WORKFLOW`. Интерфейс адаптера создан
   (`integrations/seedance/`), фейковой интеграции нет.
2. Формат промпта, который мы уже написали, **остаётся эталонным**: он описывает
   последовательность движения, физику, стартовый и финальный кадр — и переносится
   на любой из подключённых движков без переписывания.
3. Роль основного видеодвижка на время пилота занимает **Cinema Studio 3.0**.
4. Внимание при переходе: Seedance отдаёт **24 fps**, наш мастер — **30 fps**.
   Конверсия делается в `pipeline/edit/assemble_episode.py`, а не на глаз.

## 3-бис. Критическое ограничение: reference conditioning ломает identity lock

**Проверено 21.08.2026, стоимость проверки — 11 генераций.**

При передаче референсного изображения (`medias`) модель `soul_2` **принудительно включает
переписывание промпта** (`enhance_prompt: true`). Параметр не отключается: сервер отбрасывает
`enhance_prompt: false` с формулировкой «Higgsfield Soul 2.0 does not support this parameter».

Что делает переписывание с нашим промптом:

| Мы писали | Модель переписала |
|---|---|
| асимметричное усталое лицо | «striking, **model-like symmetrical** facial features» |
| серо-зелёные глаза, синий **в негативе** | «bright **blue** eyes» |
| трёхдневная щетина, борода **в негативе** | «fashionably scruffy **beard**» |
| строгий правый профиль | «**straight-on** close-up» |
| текст **запрещён** | нашивка «MNCAN O CAN», код «RN7.2292» |
| без слёз | «a single **tear** under his eye» |

Переписывание уничтожает identity lock целиком: и позитивную часть, и негативы, и ракурс.

### Правило пайплайна

1. **Reference conditioning на `soul_2` не используется для работы с идентичностью.** Никогда.
2. Кадры с лицом генерируются **только text-to-image** с дословным locked-блоком:
   в этом режиме промпт сохраняется без изменений (проверено на всех кадрах эталонов).
3. Если референс нужен по существу — используется штатный механизм консистентности
   персонажа (обучаемый Soul-ID, параметр `soul_id`), а не подстановка картинки.
4. **Каждый батч после генерации сверяется с возвращённым `params.prompt`.**
   Если он не совпадает с отправленным — результат бракуется не глядя.

Последний пункт — обязательная проверка `visual-qc` перед приёмкой любого кадра.

## 4. Проверенное ограничение генерации текста

Модели **не пишут кириллицу**: на холодном тесте латунная табличка вышла абракадаброй,
плюс модель самовольно добавила подпись поверх кадра.

**Правило pipeline:** любой читаемый текст — табличка, список жильцов, домофон,
интерфейс телефона — рисуется в композе шрифтами из `bible/TYPOGRAPHY.md`.
В негатив каждого промпта обязательно входит `text, letters, numbers, signage, watermark`.
